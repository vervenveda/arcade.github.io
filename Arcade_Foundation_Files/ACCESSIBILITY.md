# Accessibility Statement

## Commitment

Arcade™ is intended to be welcoming, readable, keyboard-accessible, and usable across desktop, tablet, and mobile devices.

The project aims to support visitors with varied vision, hearing, mobility, attention, language, and learning needs.

## Current Accessibility Features

The Arcade landing page includes or is intended to include:

- semantic headings and landmarks;
- a skip link;
- visible keyboard focus;
- native buttons, links, inputs, and select controls;
- keyboard-operable search and filters;
- text labels in addition to color;
- readable contrast;
- responsive layouts;
- reduced-motion support;
- descriptive link and button names;
- logical source order;
- touch targets sized for comfortable use;
- text that can wrap without overlapping controls;
- local functionality that does not depend on audio.

## Motion and Visual Effects

The Arcade After Dark identity uses restrained glow, color, and movement.

Animations should:

- avoid rapid flashing;
- stop or reduce when `prefers-reduced-motion` is enabled;
- never be required to understand or operate a game;
- avoid blocking reading or keyboard navigation.

## Game-Level Accessibility

Each game is maintained as an individual static page. A game should be reviewed for:

- keyboard-only play;
- screen-reader labeling;
- instructions that do not rely only on color;
- pause and reset controls;
- sufficient contrast;
- scalable text;
- mobile usability;
- reduced motion;
- understandable error and success messages.

Some older games may not yet meet every goal. Accessibility improvements should be recorded as continuing work rather than hidden.

## Reporting an Accessibility Problem

When reporting an issue, include:

- the game or page title;
- the filename or public URL;
- the browser and device;
- the assistive technology used, when relevant;
- what you expected to happen;
- what prevented access.

Do not include private or sensitive personal information.

## Review Standard

New and revised pages should be checked against WCAG 2.2 AA principles where practical for a handcrafted static project:

- perceivable;
- operable;
- understandable;
- robust.
